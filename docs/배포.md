# 배포 안내

프론트는 Vercel, 백엔드는 OCI(도쿄 리전) VM에 올린다. 도메인은 `rehearview.shop`(DNS는 Cloudflare)을 쓴다.

```
브라우저 → https://www.rehearview.shop  (Vercel, Next.js)
              └ /api/* 를 프록시 → https://api.rehearview.shop  (OCI VM: Caddy → Node 백엔드 :4000 → PostgreSQL)
```

## 1. OCI VM 준비

- 도쿄 리전에 Ubuntu 22.04 VM을 만든다. 공인 IP를 할당한다. (현재 AMD 1GB 메모리라 스왑 2GB를 만들어 둔다: `fallocate -l 2G /swapfile` 후 `mkswap`, `swapon`, `/etc/fstab` 등록)
- VCN 보안 목록(또는 NSG)에서 인바운드 TCP 80, 443을 연다. 4000(백엔드)과 5432(DB)는 열지 않는다.
- VM 안쪽 방화벽(iptables)도 80, 443을 열어야 한다. `REJECT` 규칙 앞에 넣고 저장한다.
  ```
  sudo iptables -I INPUT 5 -p tcp --dport 80 -m state --state NEW -j ACCEPT
  sudo iptables -I INPUT 6 -p tcp --dport 443 -m state --state NEW -j ACCEPT
  sudo sh -c 'iptables-save > /etc/iptables/rules.v4'
  ```
- Gmail SMTP는 465 포트로 밖으로 나간다. `smtp.gmail.com:465` 연결을 확인한다.

## 2. 서버에 설치

- Node 22.18 이상(권장 24). `.ts` 파일을 그대로 실행하므로 이 버전 이상이 필요하다.
- PostgreSQL, Caddy.
- 서비스 전용 사용자(`rehearview`)를 만들고 코드는 `/opt/rehearview-be` 에 둔다.
- DB와 사용자(`rehearview`)를 만들고, 비밀번호는 무작위로 만들어 `.env` 의 `DATABASE_URL` 에만 넣는다.

## 3. 백엔드 설정과 실행

```
git clone https://github.com/singsangsong28/rehearview-be.git /opt/rehearview-be
cd /opt/rehearview-be
npm ci                       # prisma 가 devDependencies 에 있으므로 --omit=dev 를 쓰지 않는다
npx prisma generate
npx prisma migrate deploy    # .env 의 DATABASE_URL 사용
```

`.env.example` 을 복사해 `.env` 를 만들고 서버에서 직접 값을 채운다. 비밀 값은 저장소·채팅에 올리지 않는다. `.env` 는 `rehearview` 사용자 소유, 권한 600으로 둔다 (`sudo` 로 편집한 뒤에는 `chown rehearview:rehearview` 를 다시 한다).

| 변수 | 운영 값 |
|---|---|
| `DATABASE_URL` | 서버 Postgres 주소 |
| `FRONTEND_ORIGIN` | `https://www.rehearview.shop` |
| `OAUTH_REDIRECT_BASE` | `https://www.rehearview.shop/api` (로그인 시작과 콜백이 같은 주소를 거쳐야 확인용 쿠키가 따라온다) |
| `JWT_SECRET` | 길고 무작위한 값 (개발 값과 다르게) |
| `GEMINI_API_KEY`, `GROQ_API_KEY` 등 | LLM 키 |
| `GEMINI_MODEL` | 무료 한도에 따라 정한다 (현재 `gemini-3.5-flash-lite`) |
| `LLM_TIMEOUT_MS` | `60000` |
| `*_CLIENT_ID`, `*_CLIENT_SECRET` | 소셜 로그인 키 |
| `SMTP_USER`, `SMTP_PASS` | Gmail 주소와 앱 비밀번호 |
| `TRUST_PROXY` | `1` (Caddy 한 단계. 아래 Caddy 설정과 함께 쓴다) |

`NODE_ENV=production` 은 서비스 파일(`deploy/rehearview-backend.service`)에서 설정한다. 이 값이 있어야 로그인 쿠키에 `secure` 가 붙는다.

```
sudo cp deploy/rehearview-backend.service /etc/systemd/system/
sudo systemctl enable --now rehearview-backend
```

## 4. HTTPS (Caddy)

`deploy/Caddyfile` 을 `/etc/caddy/Caddyfile` 에 넣고 `sudo systemctl reload caddy` 한다. `api.rehearview.shop` 은 Cloudflare DNS에서 VM 공인 IP를 가리키는 A 레코드(프록시 끔, DNS only)여야 한다. 인증서는 자동 발급된다.

Caddy는 기본적으로 들어온 `X-Forwarded-For` 를 지우고 접속자(Vercel 서버) IP로 덮어쓴다. 그래서 Vercel이 알려 주는 사용자 IP(`X-Vercel-Forwarded-For`)를 `header_up` 으로 넘기고 `TRUST_PROXY=1` 로 읽는다. 한계: 백엔드 주소에 직접 요청하는 사람이 이 헤더를 위조하면 요청 제한을 피할 수 있다.

확인: `https://api.rehearview.shop/health` 가 `{"ok":true}` 를 돌려주면 된다.

## 5. 프론트 (Vercel)

- `rehearview-fe` 저장소를 가져와 배포한다. 프로덕션 브랜치는 `main`.
- Environment Variables 에 `BACKEND_URL=https://api.rehearview.shop` 을 추가한다 (끝에 슬래시나 `/api` 없이). 값은 빌드 때 반영되므로 바꾸면 **다시 배포**해야 한다.
- Domains 에 `www.rehearview.shop` 과 `rehearview.shop`(www 로 이동)을 추가하고, Vercel이 알려 주는 레코드를 Cloudflare DNS에 넣는다 (프록시 끔).

## 6. 소셜 로그인 콜백 등록

각 제공사 콘솔에 `https://www.rehearview.shop/api/auth/<provider>/callback` 을 등록한다. GitHub는 콜백을 하나만 둘 수 있어 로컬 개발과 번갈아 바꿔야 한다. 네이버·카카오는 개발 중 상태에서는 멤버로 등록한 계정만 로그인되고, 일반 공개에는 검수가 필요하다.

## 7. 자동 배포 (GitHub Actions)

`.github/workflows/ci.yml` 이 아래를 한다.

- PR (dev, main 대상): Postgres를 띄워 마이그레이션 적용, 타입 체크, 테스트.
- `main` 에 병합(푸시): 테스트 통과 후 서버에 SSH로 접속해 `deploy/deploy.sh` 실행 (`git reset --hard origin/main` → `npm ci` → `prisma generate` → `prisma migrate deploy` → 서비스 재시작 → 헬스 체크).

배포 마이그레이션이 자동으로 DB를 바꾸므로, 컬럼 삭제처럼 되돌리기 어려운 마이그레이션은 사람이 확인하고 병합한다.

### 처음 한 번 설정

1. 배포 전용 키를 PC에서 만든다 (비밀번호 없이): `ssh-keygen -t ed25519 -f deploy_key -N ""`
2. 공개 키를 서버 `ubuntu` 계정의 `~/.ssh/authorized_keys` 에 아래처럼 **실행 명령을 제한해서** 한 줄 추가한다. 이 키로는 `deploy.sh` 한 가지만 실행된다.
   ```
   command="/opt/rehearview-be/deploy/deploy.sh",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAA... deploy
   ```
3. GitHub 저장소 Settings → Secrets and variables → Actions 에 등록한다.
   - `SSH_HOST`: 서버 주소 (`api.rehearview.shop` 또는 공인 IP)
   - `SSH_KEY`: 배포 전용 개인 키 내용
   - `SSH_KNOWN_HOSTS`: `ssh-keyscan -t ed25519 <SSH_HOST>` 결과 (서버 신원 고정)
4. 개인 키 파일은 등록 뒤 PC에서 지운다. 저장소·채팅에 올리지 않는다.
5. 서버에 `deploy.sh` 가 생기도록 한 번은 수동으로 `git pull` 한다.

`sudo` 가 비밀번호 없이 되는 `ubuntu` 계정을 쓰므로, 키가 새면 `deploy.sh` 만 실행되지만 `main` 의 코드가 곧 서버에서 실행된다는 점은 같다. `main` 에는 PR로만 병합한다.

## 8. DB 백업

`deploy/backup.sh` 는 매일 DB를 덤프(`/var/backups/rehearview`, root 전용)하고 14일이 지난 파일을 지운다. 서버에 한 번 설치한다.

```
sudo cp /opt/rehearview-be/deploy/backup.sh /etc/cron.daily/rehearview-backup
sudo chmod 755 /etc/cron.daily/rehearview-backup
sudo /etc/cron.daily/rehearview-backup      # 바로 한 번 실행해서 확인
sudo ls -l /var/backups/rehearview
```

- 같은 서버 디스크에만 있어서 서버를 잃으면 백업도 잃는다. 서버 밖 사본(오브젝트 스토리지, 내 PC)은 별도로 정한다.
- 복구: `zcat 파일.sql.gz | sudo -u postgres psql rehearview` (빈 DB에 넣는다).
- 탈퇴한 사용자의 정보가 백업에 최대 14일 남으므로 처리방침에 적는다.

## 9. 배포 후 확인

- 이메일 가입 → 인증 메일 수신 → 로그인
- 소셜 로그인 4종
- 서류 분석 → 음성 면접 → 리포트
- 일일 제한이 사용자별로 걸리는지 (`TRUST_PROXY` 확인)
- 개인정보처리방침의 서비스 주소·시행일·호스팅 정보가 실제와 맞는지

## 참고

- 일일 사용 제한은 서버 메모리에 있어서 재시작하면 초기화된다. 자동 배포가 재시작을 하므로 배포 때마다 초기화된다.
- Gemini 무료 티어는 모델별 하루 요청 한도가 작다 (`gemini-3.6-flash` 20회). 공개 전에는 유료 전환을 검토한다.
- Vercel 무료 플랜의 이용 조건(비영리·개인용)을 약관에서 확인한다.
