# 배포 안내

프론트는 Vercel, 백엔드는 OCI(도쿄 리전) VM에 올린다. 도메인 없이 무료 서브도메인(DuckDNS 등)과 `*.vercel.app` 주소로 시작하고, 나중에 도메인을 사면 연결만 바꾼다.

```
브라우저 → https://<앱>.vercel.app  (Vercel, Next.js)
              └ /api/* 를 프록시 → https://<서브도메인>  (OCI VM: Caddy → Node 백엔드 :4000 → PostgreSQL)
```

## 1. OCI VM 준비

- 도쿄 리전에 Ubuntu 계열 VM을 만든다. 공인 IP를 할당한다.
- VCN 보안 목록(또는 NSG)에서 인바운드 TCP 80, 443을 연다. 4000(백엔드)과 5432(DB)는 열지 않는다.
- 확인 필요: Ubuntu 이미지는 VM 안쪽 방화벽(iptables)도 막혀 있는 경우가 있다. 80, 443을 안쪽에서도 열었는지 확인한다.
- 확인 필요: Gmail SMTP는 465 포트로 밖으로 나간다. VM에서 `smtp.gmail.com:465`에 연결되는지 확인한다.

## 2. 서버에 설치

- Node 22.18 이상(권장 24). `.ts` 파일을 그대로 실행하므로 이 버전 이상이 필요하다.
- PostgreSQL, Caddy.
- 서비스 전용 사용자(`rehearview`)를 만들고 코드는 `/opt/rehearview-be` 에 둔다.

## 3. 백엔드 설정과 실행

```
git clone https://github.com/singsangsong28/rehearview-be.git /opt/rehearview-be
cd /opt/rehearview-be
npm ci                       # prisma 가 devDependencies 에 있으므로 --omit=dev 를 쓰지 않는다
npx prisma generate
npx prisma migrate deploy    # .env 의 DATABASE_URL 사용
```

`.env.example` 을 복사해 `.env` 를 만들고 서버에서 직접 값을 채운다. 비밀 값은 저장소·채팅에 올리지 않는다.

| 변수 | 운영 값 |
|---|---|
| `DATABASE_URL` | 서버 Postgres 주소 |
| `FRONTEND_ORIGIN` | `https://<앱>.vercel.app` |
| `OAUTH_REDIRECT_BASE` | `https://<앱>.vercel.app/api` (로그인 시작과 콜백이 같은 주소를 거쳐야 확인용 쿠키가 따라온다) |
| `JWT_SECRET` | 길고 무작위한 값 (개발 값과 다르게) |
| `GEMINI_API_KEY` 등 | LLM 키 |
| `*_CLIENT_ID`, `*_CLIENT_SECRET` | 소셜 로그인 키 (운영용 앱) |
| `SMTP_USER`, `SMTP_PASS` | Gmail 주소와 앱 비밀번호 |
| `TRUST_PROXY` | 프록시 단계 수. 배포 후 실제 요청의 `X-Forwarded-For` 를 보고 정한다 (Caddy만 거치면 1, Vercel 프록시까지 신뢰하면 2) |

`NODE_ENV=production` 은 서비스 파일(`deploy/rehearview-backend.service`)에서 설정한다. 이 값이 있어야 로그인 쿠키에 `secure` 가 붙는다.

```
sudo cp deploy/rehearview-backend.service /etc/systemd/system/
sudo systemctl enable --now rehearview-backend
```

## 4. HTTPS (Caddy)

`deploy/Caddyfile` 의 서브도메인을 실제 주소로 바꿔 `/etc/caddy/Caddyfile` 에 넣고 Caddy를 다시 불러온다. 서브도메인은 VM 공인 IP를 가리키게 설정한다. 인증서는 자동 발급된다.

확인: `https://<서브도메인>/health` 가 `{"ok":true}` 를 돌려주면 된다.

## 5. 프론트 (Vercel)

- `rehearview-fe` 저장소를 가져와 배포한다. 프로덕션 브랜치는 `main`.
- Environment Variables 에 `BACKEND_URL=https://<서브도메인>` 을 추가한다 (끝에 슬래시나 `/api` 없이). 값을 바꾸면 다시 배포해야 반영된다.

## 6. 소셜 로그인 콜백 등록

각 제공사 콘솔에 `https://<앱>.vercel.app/api/auth/<provider>/callback` 을 등록한다. 네이버·카카오는 서비스 URL 검수가 필요할 수 있다.

## 7. 배포 후 확인

- 이메일 가입 → 인증 메일 수신 → 로그인
- 소셜 로그인 4종
- 서류 분석 → 음성 면접 → 리포트
- 일일 제한이 사용자별로 걸리는지 (`TRUST_PROXY` 확인)
- 개인정보처리방침의 서비스 주소·시행일·호스팅 정보가 실제와 맞는지

## 참고

- 일일 사용 제한은 서버 메모리에 있어서 재시작하면 초기화된다.
- Vercel 무료 플랜의 이용 조건(비영리·개인용)을 배포 전에 약관에서 확인한다.
